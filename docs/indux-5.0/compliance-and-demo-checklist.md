# INDUX 5.0 Compliance & Demo Checklist

## Before registration / submission

- [ ] Confirm current organizer rules, selected focus area and any problem-specific brief.
- [ ] Submit one focus area only: **Digital Twin & Simulation** for this proposal.
- [ ] Verify team size, registration, abstract fields, deck format, interview instructions and deadlines on the official portal.
- [ ] Keep this pre-event concept prototype separate from the original implementation developed during the on-site 24-hour round.

## Originality and attribution

- [ ] Follow the official requirement that code/assets built during the 24-hour event are original work by the team.
- [ ] Ask organizers whether using any pre-event prototype, prompt, generated asset or code is permitted. If unclear, do not reuse it in the event build.
- [ ] Attribute permitted open-source libraries, APIs, datasets, images and model weights in the repo and slides.
- [ ] Record team contributions in Git commits/issues and maintain a clear README.

## Data, safety and privacy

- [ ] Use synthetic occupants unless explicit approvals and lawful, privacy-reviewed data access exist.
- [ ] No CCTV is connected in the current prototype. Do not say real camera tracking is implemented.
- [ ] Avoid face recognition or identity tracking. Any future sensor use should minimize data and prefer authorized aggregate occupancy counts.
- [ ] Label simulated outputs; do not call them validated real-world evacuation times or life-safety predictions.
- [ ] Include a visible no-safe-route state and state uncertainty/model assumptions.
- [ ] Do not present the product as a replacement for fire codes, trained responders or approved evacuation plans.

## Demo readiness

- [ ] Start from a known scenario and reset cleanly.
- [ ] Show the core user flow from scenario setup to route comparison and result.
- [ ] Show one failure/edge case, such as blocked exits or no valid route.
- [ ] Use repeated, matched runs for any claimed performance comparison.
- [ ] Show actual measured numbers, sample count, model assumptions and baseline.
- [ ] Rehearse within the exact pitch time; prepare a local backup video and a no-network fallback.
- [ ] Be ready to explain every technical term and each team member's contribution.
