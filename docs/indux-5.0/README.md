# SafeTwin AI × INDUX 5.0

Competition preparation pack for **INDUX 5.0 — International 24-hour AI Hackathon, Vikrant University, Gwalior**.

## Chosen focus area

**Digital Twin & Simulation** is the single selected focus area. SafeTwin AI creates a building-scale twin and simulates emergency routes, occupant movement and congestion. Environment, Health & Safety is the impact domain, not a second selected theme.

## Competition fit

| INDUX evaluation area | SafeTwin evidence to prepare | Honest current status |
|---|---|---|
| Innovation & originality | Dynamic hazard-aware routing and side-by-side evacuation what-if comparison | Prototype concept; validate novelty against the official problem statement and mentor feedback |
| Real-world impact | Building managers, campuses and emergency planners rehearse scenarios before an incident | Intended impact; no measured life-safety outcome claim |
| AI/ML technical depth | Graph pathfinding with exit capacity + hazard cost, crowd-flow simulation, measured strategy comparison | Current UI uses illustrative client-side heuristics; this is a key 24-hour build gap |
| Feasibility & scalability | Start with one verified floor, then multi-floor building models and authorized aggregate occupancy inputs | CCTV / live occupancy integration is future work, not connected |
| Prototype & demo | Click a hazard, observe a changing twin, compare plans and show a route decision | Current web demo is illustrative and not an operational system |
| Presentation clarity | 3-minute story: risk → twin → scenario → route comparison → limits | See `pitch-script.md` and `pitch-deck-outline.md` |

## Important originality rule

INDUX's official repository says code and assets made during the 24-hour on-site round must be original work by the team; open-source libraries/APIs are permitted with attribution. Therefore, treat this current repo as **pre-event preparation / concept validation only**. Do **not** copy its implementation, source, generated SVGs, UI code, or assets into the on-site deliverable if that would violate the event's originality rules. During the event, rebuild the submitted implementation from scratch, using the problem statement and organizer permissions as the authority. Keep this note and ask the organizers if the status of preparatory prototypes is unclear.
